# Sage V0.1 LangGraph Manual Setup and Testing Guide

> **Status:** Historical testing guide. Its commands are not current; use
> [`../docs/testing.md`](../docs/testing.md) instead.

## Purpose

This guide helps a first-time user set up Sage V0.1, build its Docker
sandbox, verify the project-owned LangGraph runtime, submit a local issue, and
inspect the resulting candidate patch. It includes a single-command path and
recovery steps so a setup failure does not leave the user guessing.

V0.1 changes the internal reasoning runtime only. The CLI, source-repository
isolation, Docker sandbox, issue format, run artifacts, and exit codes remain
compatible with V0.

The current project identifiers are Sage-specific. The command name, Python
package, configuration prefix, Docker names, and default artifact directory all
changed together; their underlying behavior and values remain the same.

> A live solve sends the issue and model-selected repository context to OpenAI
> and may incur API usage charges. Setup, unit tests, graph rendering, and the
> sandbox smoke test do not call OpenAI.

## What the all-in-one command does

After you have a committed target repository and an issue file, this command
handles the complete controller workflow:

```bash
make first-run \
  REPO=/absolute/path/to/committed/repository \
  ISSUE=/absolute/path/to/issue.md
```

It performs six ordered steps:

1. syncs the locked Python 3.14 environment with uv;
2. builds the `sage-sandbox:v0` Docker image;
3. smoke-tests Git, Python, and ripgrep inside a disposable network-disabled
   container;
4. checks Git, uv, Docker, the daemon, image, API key, and virtual environment;
5. runs all deterministic tests and Python compilation; and
6. runs the live issue solve.

If `.env` exists, the command loads it. If no API key is configured and the
terminal is interactive, it prompts for the key with input hidden and keeps it
only in the command environment. It does not write the entered secret to disk.
For non-interactive use, export `OPENAI_API_KEY` or create `.env` first.

The command stops on the first real failure and prints which numbered step
failed. A normal no-change CLI result is reported as a warning rather than as a
Make failure.

## 1. Prerequisites

Run all commands from the Sage repository root, which contains
`Makefile`, `apps/`, `docker/`, and `specs/`.

Required host tools:

| Tool | Verify | Why it is needed |
| --- | --- | --- |
| Git | `git --version` | Resolves and clones the committed target revision. |
| uv | `uv --version` | Installs the locked Python environment. |
| Python 3.14 | `uv python find 3.14` | Required by the backend project. |
| Docker | `docker --version` | Builds and runs the repository sandbox. |
| Docker daemon | `docker info` | Required for image and container operations. |
| GNU Make | `make --version` | Provides the documented workflows. |
| Bash | `bash --version` | Runs Make recipes and optional `.env` loading. |

If Python 3.14 is missing but uv is installed:

```bash
uv python install 3.14
```

If Docker is installed but `docker info` fails, start Docker Engine or Docker
Desktop before continuing. On Linux, make sure the current user is authorized
to access the daemon.

## 2. Configure the OpenAI model

### Option A: let `first-run` prompt securely

Do not create `.env`. Run `make first-run ...` from an interactive terminal.
When prompted, paste the API key; the characters are not echoed. The key is
available only to that Make process and is not stored.

### Option B: create an ignored `.env`

```bash
make env
```

Edit `.env` and set:

```dotenv
OPENAI_API_KEY=replace-with-your-real-key
OPENAI_MODEL=gpt-5.4-mini
```

The remaining values already have bounded defaults:

```dotenv
SAGE_MAX_TURNS=30
SAGE_RUNS_DIR=.sage/runs
SAGE_SANDBOX_IMAGE=sage-sandbox:v0
SAGE_COMMAND_TIMEOUT_SECONDS=60
SAGE_MAX_TOOL_OUTPUT_CHARS=12000
```

Protect the local file when appropriate:

```bash
chmod 600 .env
```

Never commit `.env`, paste the key into an issue, or put it in the target
repository. The key remains on the host and is not passed to Docker or graph
state.

## 3. Prepare a safe target repository

The target must be a local Git working tree with at least one commit. Use a
throwaway repository for the first live test.

Verify an existing target:

```bash
export TARGET_REPO=/absolute/path/to/target

git -C "$TARGET_REPO" rev-parse --show-toplevel
git -C "$TARGET_REPO" rev-parse --verify HEAD
git -C "$TARGET_REPO" status --short
git -C "$TARGET_REPO" log -1 --oneline
```

Important behavior:

- Sage clones only the selected committed revision.
- Uncommitted and untracked source files are intentionally excluded.
- The source checkout is never mounted into Docker or modified.
- Candidate changes are made under `.sage/runs/<run-id>/repo`.

If the issue depends on a local change, commit that non-secret change on an
appropriate branch first. Do not point `REPO` at the parent of a Git working
tree.

## 4. Write the issue

Create a template without overwriting an existing file:

```bash
make new-issue ISSUE=/absolute/path/to/my-issue.md
```

Edit it with concrete behavior and a testable finish condition. A good issue
contains:

- the current incorrect or missing behavior;
- the expected behavior;
- the relevant component or a reproduction;
- compatibility constraints; and
- an exact test command or acceptance criteria.

Example:

```markdown
# Fix integer addition

`calculator.add(a, b)` subtracts `b`. Return the mathematical sum instead.

## Acceptance criteria

- `add(2, 3)` returns `5`.
- `add(-1, 1)` returns `0`.
- Keep the public function signature unchanged.
- Run `python3 -m unittest discover -v`.
```

The issue may live outside the target repository. It must be readable UTF-8
text and must not contain credentials or unnecessary sensitive information.

## 5. Run the single-command workflow

Use absolute paths:

```bash
make first-run \
  REPO="$TARGET_REPO" \
  ISSUE=/absolute/path/to/my-issue.md
```

Optional overrides:

```bash
make first-run \
  REPO="$TARGET_REPO" \
  ISSUE=/absolute/path/to/my-issue.md \
  BASE_REF=HEAD \
  SANDBOX_IMAGE=sage-sandbox:v0
```

The first run may take several minutes because uv and Docker download build
inputs. The live solve starts only after deterministic checks pass.

A changed result prints:

```text
Sage V0

Run: <run-id>
Base: <base-sha>
Model: <configured-model>

Changed files:
  <path>

Summary:
  <model summary>

Workspace:
  <run-directory>/repo

Patch:
  <run-directory>/diff.patch
```

Copy the run directory path. The CLI intentionally keeps the `Sage V0`
product label for compatibility even though the internal runtime is V0.1.

## 6. Verify the LangGraph migration without an API call

Confirm new runtime dependencies:

```bash
uv tree --project apps/agent | rg "langgraph|langchain-core|langchain-openai"
```

Confirm the removed Agents SDK has no active dependency:

```bash
uv tree --project apps/agent | rg "openai-agents"
```

Expected: the first command shows all three LangGraph/LangChain packages. The
second prints nothing and exits `1`, which means no match.

Audit active source and tests:

```bash
rg -n "from agents|import agents|openai_agents|OpenAIAgentsRuntime" \
  apps/agent/src apps/agent/tests apps/agent/pyproject.toml
```

Expected: no matches.

Verify the installed Sage package and public commands:

```bash
uv run --project apps/agent python -c "import sage; print(sage.__name__)"
uv run --project apps/agent sage --help
make help
```

Expected: the import prints `sage`, CLI help begins with `usage: sage`, and the
Make help heading is `Sage V0.1 helper commands`.

Render the compiled graph:

```bash
make graph
```

Expected Mermaid topology:

```text
__start__ -> agent
agent -> tools | finalize | turn_limit | invalid_response
tools -> agent
finalize | turn_limit | invalid_response -> __end__
```

This command builds the real graph with test fakes. It does not create a
provider client or call OpenAI.

Run deterministic verification:

```bash
make check
```

Expected at this implementation revision: 68 passing tests followed by a
successful source compilation. The 42 runtime tests cover tool schemas,
routing, nodes, topology, full fake-model traversal, turn limits, result
validation, and exception translation.

## 7. Inspect a completed run

```bash
export RUN_DIR=/absolute/path/to/.sage/runs/<run-id>
make run-status RUN_DIR="$RUN_DIR"
```

The directory must contain:

```text
request.json
metadata.json
issue.md
agent-final.json
changed-files.json
diff.patch
repo/
```

Verify:

- `metadata.json` contains the configured model and sandbox image;
- `agent-final.json` contains `summary`, `changed_files_claimed`, and
  `remaining_uncertainty`;
- `changed-files.json` matches `git -C "$RUN_DIR/repo" diff --name-only`;
- `diff.patch` matches the candidate diff;
- no API key, authorization value, model message history, or provider payload
  was persisted; and
- the original target repository remains unchanged.

The model's claimed files are informational. Git-derived `changed-files.json`
and `diff.patch` are authoritative.

## 8. Test the generated candidate

Choose a command supported by the selected sandbox image:

```bash
make run-test \
  RUN_DIR="$RUN_DIR" \
  TEST_COMMAND="python3 -m unittest discover -v"
```

The command runs in a fresh network-disabled container over the candidate
checkout. The default image includes Bash, Git, Python 3, and ripgrep. Projects
requiring Node, Java, Go, Rust, databases, or third-party packages need a custom
image with those dependencies installed at image-build time.

## 9. Test failure and cleanup behavior

### No-change result

The raw CLI exits `2` when a valid structured result produces no Git diff.
`make solve` and `make first-run` convert this into a clear warning and Make
success. Inspect `agent-final.json` for the reason.

### Model-turn limit

For a deliberate limit test, use a task requiring inspection and run:

```bash
SAGE_MAX_TURNS=1 make solve \
  REPO="$TARGET_REPO" \
  ISSUE=/absolute/path/to/my-issue.md
```

If the first decision requests a repository tool, expected behavior is a
concise `Model turn limit (1)` error. The pending tool must not run because no
model decision would remain to consume its result.

### Container cleanup

After success and intentional failure:

```bash
docker ps --filter "name=sage-"
```

Expected: no container from a completed run. An abruptly killed host process
may leave a stale container. Inspect exact names with `docker ps --all` before
removing only the confirmed stale container.

## 10. Troubleshooting

### Immediate `ValueError` before the first model decision

The original V0.1 runtime let `ChatOpenAI` choose its API endpoint. A model such
as `gpt-5.4-mini` selected Chat Completions, where the OpenAI parsing helper
rejects non-strict function tools when a Pydantic response format is present.
The failure happened locally after graph startup and before the HTTP request,
so the normal error only showed `LangGraph agent run failed (ValueError)`.

The current runtime explicitly selects the Responses API. Verify the exact
regression without making an API call:

```bash
uv run --project apps/agent pytest \
  apps/agent/tests/runtimes/test_langgraph_runtime.py \
  -k responses_request
```

Expected: one passing test. It constructs the first `gpt-5.4-mini` payload and
checks for `input` and `text_format` rather than the incompatible Chat
Completions fields `messages` and `response_format`.

If an expected repository operation rejects a path, command, or patch, the
graph now returns that bounded error to the model as an error tool result. The
model may correct the request on a later turn; unexpected programming errors
still terminate the graph. All retries remain bounded by
`SAGE_MAX_TURNS`.

| Symptom | Likely cause | Recovery |
| --- | --- | --- |
| `uv: command not found` | uv is absent or not on `PATH`. | Install uv, open a new terminal, run `uv --version`, then retry. |
| Python 3.14 cannot be found | Required interpreter is missing. | Run `uv python install 3.14`, then `make setup`. |
| Dependency download fails | Host DNS, proxy, or firewall blocks PyPI. | Restore host network access and rerun `make setup`; sandbox networking is unrelated. |
| Docker daemon is unreachable | Docker is stopped or permission is denied. | Start Docker, run `docker info`, then retry. |
| Sandbox image is missing | Build did not complete or the tag differs. | Run `make sandbox-build` and `make sandbox-smoke`. |
| API key is empty | No `.env`, export, or interactive key was supplied. | Run interactively, export the key, or use `make env`; never commit it. |
| Model authentication/access error | Key, quota, billing, or model access is invalid. | Verify the API project and `OPENAI_MODEL`; retry with `make solve-debug`. |
| Graph fails immediately with `LangGraph agent run failed (ValueError)` before any model decision | The environment may contain the pre-fix runtime that allowed `ChatOpenAI` to select Chat Completions while binding non-strict tools to a Pydantic response format. | Update the checkout, run `make setup`, then `make check`. The current runtime explicitly uses the Responses API and tests the first request payload with `gpt-5.4-mini`. |
| Target is not a Git repository | `REPO` points to the wrong directory. | Run `git -C <path> rev-parse --show-toplevel` and use that path. |
| Base ref does not resolve | The local ref is missing or not a commit. | Verify with `git -C <repo> rev-parse --verify '<ref>^{commit}'`. |
| Agent cannot see a file | The file is uncommitted or excluded by the selected base. | Commit the required non-secret file and choose that commit. |
| Tool command is unavailable | Default sandbox lacks project tooling. | Build and select a minimal custom sandbox image. |
| Model turn limit reached | The issue needs more decisions than configured. | Focus the issue or increase `SAGE_MAX_TURNS` by a bounded amount. |
| A patch or repository tool call is rejected | The model supplied an invalid path, command, or patch. | The graph returns the bounded error to the model for correction. If the run still fails, use `make solve-debug` and inspect the safe error category without sharing secrets or full repository contents. |
| Graph recursion limit reached | A graph invariant failed. | Run focused runtime tests and `make graph`; report the debug traceback. |
| Run directory lacks final artifacts | Runtime failed after initial artifact creation. | Inspect the partial run and rerun with `make solve-debug`; do not treat it as completed. |

Debug logs must not contain the API key, full prompt, full issue, patches, file
contents, or complete tool arguments. Redact sensitive paths and values before
sharing a failure report.

## Completion checklist

- [ ] Host prerequisites and Docker daemon are ready.
- [ ] The API key is configured without entering source control.
- [ ] The target path is a committed Git repository.
- [ ] The issue has concrete acceptance criteria.
- [ ] `make first-run REPO=... ISSUE=...` completes setup and reaches the solve.
- [ ] `make graph` shows all five nodes and the `tools -> agent` loop.
- [ ] The dependency and removed-code audits pass.
- [ ] `make check` reports 68 passing tests and successful compilation.
- [ ] A live solve creates the expected run artifacts.
- [ ] Candidate tests pass in an appropriate sandbox image.
- [ ] Git-derived files and patch match the candidate checkout.
- [ ] The original source checkout remains unchanged.
- [ ] No secret appears in graph state, Docker, logs, or artifacts.
- [ ] No completed-run container remains active.

When these checks pass, V0.1 has preserved the V0 issue-to-patch behavior while
moving model decisions, tool routing, termination, and limits into the
project-owned LangGraph state machine.
